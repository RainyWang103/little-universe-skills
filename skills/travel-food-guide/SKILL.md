# Travel Food Guide

以中文交付，保留当地店名。默认假设：两位女生同行（用户与同行伙伴），场景多为旅行目的地、tasting、餐厅周；用户另有说明时以当次为准。本 skill 只做餐饮深度，不排整天行程；付款、代订、对外发消息须遵守 safety-charter，且需用户针对该次动作的明确授权。

开始前与输出前读取下列参考（摘要不能替代细则）：

1. [用餐 brief 与默认假设](references/dining-brief.md)：硬约束与软偏好；默认同行与场景。
2. [排序优先级](references/ranking-priority.md)：当地特色 → 当季可吃到 → fine dining → 其他条件。
3. [研究、多源评分与注水过滤](references/research-verification.md)：米其林、黑珍珠、大众点评、小红书、Google Maps 及地区适用信源；中国大陆默认信源组合与评论深度；交叉验证与降权规则。
4. [实体消歧](references/entity-disambiguation.md)：同城同名／近似名／多门店；未确认不进主推。
5. [推荐卡片结构](references/recommendation-card.md)：顶部决策层（主推序＋力度／排除／备注／证据／状态）；单店含推荐力度与可感「为什么去」。
6. [一日餐饮节奏](references/pacing.md)：正餐／轻食／咖啡错开与过敏话术。
7. [场景类型卡](references/type-cards.md)：正餐、精品咖啡／特调、酒吧。
8. [与行程交接](references/itinerary-handoff.md)：未定稿只留美食文档；可写回后再交主推。

## 执行顺序

1. 整理 brief（含默认两人假设）；只追问会改变推荐的关键未知。
2. 按排序优先级生成候选池，再用类型卡过滤（咖啡排除快餐连锁与纯打卡；酒吧以可靠榜单／酒单评价为主）；口头店名先做实体消歧。
3. 对拟主推对象做多源核验与注水过滤；**中国本地须按点评／美团店页＋小红书＋地图默认组合与评论深度**，WebSearch 只当线索；达不到交叉验证的降为备选或剔除。
4. **先写决策层（主推序≤3 并点明力度差异／已排除＋原因／必做备注／证据一句／未定稿或可写回），再写推荐卡片**（含推荐力度与可感理由）；偏好微调时先改顶栏与排除表。
5. 需要嵌进某天时附一日节奏；与旅行规划师配合时：未定稿不交行程，用户定序或「可写回」后只交主推＋短备选＋必做备注，不改整体日程主权。

不得编造星级、歇业、菜品、电话或「已确认」状态；做不到的核验须坦白并标「需核实」。
